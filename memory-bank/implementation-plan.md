# NL-Mesh-Inspect MVP 实施计划

## 项目概述

**MVP目标**: 实现通过自然语言描述STL文件中的顶点和面信息，并用文字总结工件特征。

**示例输出**: "这是一个带有四个 M6 螺纹孔的长方形支架，中心有一个直径为 20mm 的圆槽，边缘进行了 2mm 的倒角处理"

## 技术栈选择

- **前端**: Three.js + React (本地开发环境)
- **后端**: Python + FastAPI + Trimesh
- **AI**: GPT-4o API (结构化输出)
- **文件格式**: STL

## 实施步骤 (按顺序执行)

### 阶段1: 基础环境搭建 (Day 1)

**步骤1.1**: 创建项目基础结构
- 创建前端目录结构 (src/components, src/utils, src/hooks)
- 创建后端目录结构 (api/routes, api/services, api/models)
- 配置 package.json 和 requirements.txt

**验证测试**: 运行 `npm install` 和 `pip install -r requirements.txt` 无错误

**步骤1.2**: 设置开发服务器
- 前端: 配置 React 开发服务器 (端口 3000)
- 后端: 配置 FastAPI 开发服务器 (端口 8000)
- 配置 CORS 允许前端访问后端API

**验证测试**: 访问 http://localhost:3000 和 http://localhost:8000/docs 都能正常打开

### 阶段2: STL文件处理基础 (Day 2)

**步骤2.1**: 实现STL文件上传功能
- 前端: 创建文件上传组件，支持.stl文件
- 后端: 创建文件上传API端点，保存到临时目录

**验证测试**: 上传一个简单STL文件，确认文件被正确接收和保存

**步骤2.2**: 实现STL文件解析
- 后端: 使用Trimesh解析STL文件，提取顶点、面、法线等基础信息
- 返回文件的基本统计信息 (顶点数、面数、边界框尺寸)

**验证测试**: 解析一个立方体STL文件，正确返回6个面、8个顶点、边界框尺寸

### 阶段3: 基础3D可视化 (Day 3)

**步骤3.1**: 集成Three.js基础渲染
- 前端: 创建Three.js场景，设置基础光照和相机
- 实现STL模型加载和显示功能

**验证测试**: 上传STL文件后，在3D视图中正确显示模型

**步骤3.2**: 实现基础交互功能
- 旋转: 鼠标拖拽旋转模型
- 缩放: 鼠标滚轮缩放
- 平移: 右键拖拽平移

**验证测试**: 所有交互操作都能正常工作，模型响应正确

### 阶段4: 几何特征识别 (Day 4)

**步骤4.1**: 实现基础几何特征检测
- 后端: 使用Trimesh检测平面、圆柱面、边界边
- 实现简单的孔洞检测算法

**验证测试**: 对一个带孔的模型，正确识别出孔洞数量和位置

**步骤4.2**: 实现尺寸测量功能
- 计算模型的边界框尺寸 (长宽高)
- 检测主要特征的近似尺寸

**验证测试**: 对一个已知尺寸的测试模型，测量结果误差在5%以内

### 阶段5: 自然语言处理集成 (Day 5)

**步骤5.1**: 设计结构化输出模板
- 定义描述模板: "这是一个[形状]的[工件类型]，具有[特征1]、[特征2]..."
- 设计GPT-4o的提示词模板

**验证测试**: 手动构造测试数据，验证模板格式正确

**步骤5.2**: 集成GPT-4o API
- 后端: 创建AI服务模块，调用GPT-4o结构化输出
- 将几何特征数据转换为自然语言描述

**验证测试**: 对一个简单模型，AI能生成合理的描述文本

### 阶段6: 用户界面整合 (Day 6)

**步骤6.1**: 创建自然语言输入界面
- 前端: 添加聊天式输入框
- 实现基本的指令解析和响应显示

**验证测试**: 用户输入"描述这个模型"，系统返回描述文本

**步骤6.2**: 实现高亮显示功能
- 根据AI描述的特征，在3D模型中高亮对应部分
- 添加图例说明不同颜色代表的特征

**验证测试**: 描述中提到"孔洞"时，对应的孔洞区域被高亮显示

### 阶段7: MVP集成测试 (Day 7)

**步骤7.1**: 端到端功能测试
- 测试完整流程: 上传 → 解析 → 交互 → 描述 → 高亮
- 验证多个不同类型模型的兼容性

**验证测试**: 至少3个不同类型的STL文件都能正常工作

**步骤7.2**: 错误处理和用户体验优化
- 添加加载状态指示
- 实现错误信息的友好显示
- 优化响应速度

**验证测试**: 上传无效文件时显示清晰错误信息，操作过程有加载提示

## 验证流程

每个步骤完成后:
1. 运行相关测试验证功能正确性
2. 等待用户确认测试通过
3. 在progress.md中记录完成的工作
4. 在architecture.md中更新架构洞察
